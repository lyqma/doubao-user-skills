# 错题本（自我改进）

## 核心规矩
**同一个错，犯第二次就是无能。**
错题本就是让你永远不犯第二次。

## 错题本放哪
在当前工作目录下建一个文件夹：`.错题本/`
里面三个文件：

```
.错题本/
├── 错误记录.md      ← 命令跑挂、API报错、操作失败
├── 纠正记录.md      ← 用户亲口纠正过你的话
└── 经验记录.md      ← 反复踩出来的最佳做法
```

## 什么时候必须记（触发就记，不许拖延）

### 触发一：报错了
任何命令失败、脚本报错、工具返回 error，**不要急着重试**，先记一笔到 `错误记录.md`：

```
## YYYY-MM-DD HH:MM
- 我干了啥：
- 报了啥错：
- 真正原因：
- 下次咋办：
```

### 触发二：用户纠正你
只要用户说"不对"、"不是这样"、"我要的是XX不是YY"、"你又搞错了"——**立刻停手**，把用户的原话和正确做法记到 `纠正记录.md`：

```
## YYYY-MM-DD HH:MM
- 我之前理解成：
- 用户实际要的是：
- 用户原话："......"
- 下次遇到类似的，应该先问清楚：
```

### 触发三：发现更好的做法
干着干着发现"哦原来这么干更省事"，记到 `经验记录.md`：

```
## YYYY-MM-DD
- 场景：
- 以前的笨办法：
- 现在的好办法：
- 为什么好：
```

## 什么时候必须读错题本
**每次开新任务之前**，先读一遍这三个文件（哪怕只读最近 10 条）。
特别是：
- 用户说"又是这个错"、"你怎么又忘了"
- 遇到跟之前类似的活
- 要跑一条以前跑挂过的命令

## 禁止
- 不许因为"错得小"就不记。小错攒多了就是大毛病
- 不许记完不读。错题本是活的，不是日记
- 不许编造错误记录。没发生就别写
- 跨项目的经验（比如 Windows 下路径转义、PowerShell 的 $_ 被吃掉这种通用坑）直接记到 `经验记录.md`，所有项目通用

## 跟用户汇报
用户问"你最近踩过啥坑"的时候，把 `错误记录.md` 最近 5 条念给他听，外加一句"现在都不犯了"。
